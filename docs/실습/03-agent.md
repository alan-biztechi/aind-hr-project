# 실습 ③. Agent로 "테스트 케이스 → 엑셀 정리" 전담 만들기

> **이론 선행**: [04. Kiro의 부가 기능](../이론/04-부가기능.md) (Agent 파트)
>
> 프로젝트를 하다 보면 **테스트 케이스를 표로 정리할 일**이 끝없이 생깁니다.
> 매번 "이 기능 테스트 케이스를 엑셀로 뽑아줘, 열은 이렇게..."를 반복하는 대신,
> **그 일만 하는 전용 Agent**를 한 번 만들어 두고 호출하면 됩니다.

---

## 0. 실습 목표

- 특정 작업(테스트 케이스 정리)에 **역할·도구·권한을 묶은 Agent**를 만든다.
- Agent에 **코드 읽기 + Python 실행(엑셀 생성)** 권한만 주고, **코드 수정은 막는다.**
- 실습 ①에서 만든 **"직원 이름 검색" 기능의 테스트 케이스를 `.xlsx`로** 뽑아본다.

---

## 1. 왜 Agent로 만드나

이 작업은 매번 똑같은 세팅이 필요합니다.

- 역할: "너는 QA 엔지니어다. 소스를 읽고 테스트 케이스를 표로 정리한다."
- 입력: 대상 기능의 컨트롤러/서비스 코드
- 출력 형식: 정해진 열(TC ID, 시나리오, 입력, 기대결과 ...)의 **엑셀 파일**
- 제약: 테스트 케이스만 정리한다. **운영 코드는 건드리지 않는다.**

매번 이걸 프롬프트로 설명하는 대신 **Agent 하나로 고정**하면, 다음부터는 "직원 검색 기능 테스트 케이스 뽑아줘" 한마디로 끝납니다. 팀원과 공유도 됩니다.

> Agent = **역할 + 쓸 수 있는 도구 + 권한 + 시작 맥락**을 묶은 "이름 붙은 설정". (이론 04장)

---

## 2. 사전 준비: Python + openpyxl

엑셀(`.xlsx`) 생성은 Python의 `openpyxl`로 합니다.

```bash
python3 --version          # 3.x 확인
python3 -c "import openpyxl; print(openpyxl.__version__)"
# 없으면:
pip3 install openpyxl
```

---

## 3. Agent 만들기 — `.kiro/agents/`에 md 파일 직접 작성

Agent 설정은 **`.kiro/agents/{이름}.md`** 파일로 둡니다. UI 없이 파일을 직접 만들면 구조가 그대로 보여서 이해가 빠릅니다. 이 파일을 커밋하면 팀 전체가 같은 Agent를 씁니다.

포맷은 **front matter(설정) + 본문(시스템 프롬프트)** 입니다.

### 작성할 파일: `.kiro/agents/testcase-excel.md`

```markdown
---
name: testcase-excel
description: 기능의 테스트 케이스를 분석해 엑셀(.xlsx)로 정리하는 QA 전용 에이전트
tools: ["read", "shell", "write"]
toolsSettings:
  shell:
    allowedCommands: ["python3 .*", "pip3 install .*"]
    deniedCommands: ["rm .*", "git .*"]
  write:
    allowedPaths: ["docs/testcases/**"]
  read:
    allowedPaths: ["./src/**", "./docs/**"]
---
# 역할
너는 이 프로젝트의 QA 엔지니어다. 주어진 기능의 소스 코드를 읽고,
테스트 케이스를 도출해 **엑셀 파일(.xlsx)** 로 정리한다.

# 작업 절차
1. 대상 기능의 Controller/Service/Mapper 코드를 읽고 입력·분기·예외를 파악한다.
2. 정상 케이스 + 경계값 + 예외 케이스를 빠짐없이 뽑는다.
3. 아래 열을 가진 표로 정리한다:
   TC ID | 기능 | 시나리오 | 사전조건 | 입력 | 기대 결과 | HTTP 상태 | 비고
4. Python(openpyxl)으로 `docs/testcases/{기능}.xlsx` 파일을 생성한다.
   - 1행은 헤더, 헤더는 굵게 + 배경색
   - 열 너비는 내용에 맞게 조정
   - 한국어가 깨지지 않도록 저장

# 제약 (중요)
- 운영 코드(src/**)는 **읽기만** 한다. 절대 수정하지 않는다.
- 테스트 케이스 엑셀은 `docs/testcases/` 아래에만 생성한다.
- 추측하지 말고 코드에 근거해 케이스를 작성한다.
```

### 각 필드가 하는 일

| 필드                    | 설명                                                                     |
| ----------------------- | ------------------------------------------------------------------------ |
| `name`                | Agent 식별자. 세션에서 이 이름으로 선택한다.                             |
| `description`         | 이 Agent가 하는 일.                                                      |
| `tools`               | 쓸 수 있는 도구 — 여기선 읽기/셸/쓰기만. (코드 수정·삭제 도구는 안 줌) |
| `toolsSettings.shell` | 셸은`python3`/`pip3 install`만 허용, `rm`·`git`은 차단          |
| `toolsSettings.write` | 쓰기는`docs/testcases/` 아래로만 제한                                  |
| `toolsSettings.read`  | 읽기는`src/`, `docs/`로 제한                                         |
| 본문(`# 역할` 이하)   | Agent의**시스템 프롬프트** (역할·절차·제약)                      |

> ℹ️ `toolsSettings`로 **쓰기는 `docs/testcases/`에만, 셸은 python만** 허용했습니다.
> 이렇게 Agent의 손이 닿는 범위를 좁혀두면, 테스트 정리 중 실수로 운영 코드를 건드릴 일이 없습니다. (이것이 Agent로 묶는 핵심 이점)

> ⚠️ **파일 확장자는 반드시 `.md`로 만드세요.** `.json`으로 만들면 Kiro가 Agent 목록에 띄우지 못합니다.
>
> 파일을 저장하면 Kiro가 인식합니다. **새 세션(새 채팅)을 연 뒤** 세션 Agent 드롭다운(기본값 `Default` 자리)을 열면, BUILT-IN 목록 아래에 `testcase-excel`이 보입니다. 이게 보이면 성공입니다.
>
> 안 보이면: ① `.md` 확장자가 맞는지 확인 → ② 새 채팅을 다시 열기 → ③ 그래도 안 되면 `Cmd+Shift+P` → "Reload Window" 후 새 채팅에서 재확인.

## 4. 사용해보기: "직원 이름 검색" 테스트 케이스 뽑기

실습 ①에서 추가한 `GET /v1/employees/search?name=` 기능으로 테스트합니다.

1. 채팅 입력창 아래의 **세션 Agent 드롭다운**(기본값 `Default` 자리)을 열어 **`testcase-excel`**을 선택합니다.
2. 요청합니다.
   ```text
   직원 이름 검색 기능(/v1/employees/search)의 테스트 케이스를 엑셀로 정리해줘.
   ```
3. Agent가 하는 일:
   - `EmployeeController` / `EmployeeService` / `EmployeeMapper.xml`을 **읽기**
   - 케이스 도출 (부분 일치 / 공백 처리 / 빈 검색어 / 결과 없음 / 퇴사자 포함 여부 등)
   - Python으로 `docs/testcases/employee-search.xlsx` **생성**

### 뽑히면 좋은 케이스 예시

| TC ID | 시나리오       | 입력(name)           | 기대 결과                              | HTTP         |
| ----- | -------------- | -------------------- | -------------------------------------- | ------------ |
| TC-01 | 이름 부분 일치 | `김`               | "김"이 포함된 직원 목록                | 200          |
| TC-02 | 결과 없음      | `존재하지않는이름` | 빈 배열                                | 200          |
| TC-03 | 빈 검색어      | (빈 값)              | 요구사항에서 정한 정책대로             | 200 또는 400 |
| TC-04 | 앞뒤 공백      | `김`               | trim 후 "김"으로 검색                  | 200          |
| TC-05 | 응답 형태      | `김`               | `EmployeeResponse`(부서명 포함) 형태 | 200          |

생성된 `docs/testcases/employee-search.xlsx`를 열어 헤더·내용을 확인합니다.

## 5. 완료 체크리스트

- [ ] `testcase-excel` Agent를 만들었다. (설정이 `.kiro/agents/`에 파일로 생겼다)
- [ ] Agent의 쓰기 권한이 `docs/testcases/`로 제한되어 있다.
- [ ] Agent로 직원 검색 기능의 테스트 케이스 `.xlsx`를 생성했다.
- [ ] 엑셀을 열어 헤더/케이스가 코드 근거로 채워졌는지 확인했다.
- [ ] 실행 중 운영 코드(`src/**`)가 수정되지 않았다.

---

## 5-1. 더 나아가기 — Agent를 Workflow에 연결하기 (참고)

지금까지는 채팅에서 Agent를 **직접 골라** 한 번씩 호출했습니다. 여기서 한 걸음 더 나가면, 만들어 둔 커스텀 Agent를 **Workflow의 한 스텝으로 연결**해 자동 파이프라인의 일부로 돌릴 수 있습니다.

- Workflow는 **여러 스텝을 순서/반복/병렬로 엮은 실행 레시피**입니다. 각 스텝에 **어떤 Agent로 실행할지**를 지정할 수 있고, 여기에 우리가 만든 `testcase-excel` 같은 커스텀 Agent를 넣을 수 있습니다.
- 그래서 예를 들어 **"① 기능 구현 → ② 코드 리뷰 → ③ `testcase-excel`로 테스트 케이스 엑셀 생성"** 처럼, 사람이 매번 Agent를 바꿔 호출하지 않아도 **한 번 실행으로 테스트 케이스 정리까지 자동**으로 이어지게 만들 수 있습니다.
- 실행된 Workflow는 Kiro의 **WORKFLOWS 패널 > WORKFLOW RUNS** 에 기록으로 남습니다. (앞서 본 `testcase-직원조회` 같은 항목이 그 실행 기록입니다.)

> 요약하면, **Steering(공통 규칙) + Agent(전문 역할) + Workflow(자동 파이프라인)** 를 조합하면
> "직접 호출하는 전문 담당자"를 넘어 **"자동 흐름 속에서 알아서 일하는 담당자"**로까지 확장할 수 있습니다.

---

## 6. 돌아보기

- Agent는 **"역할·도구·권한이 고정된 담당자"**입니다. 매번 세팅을 반복하지 않고, 한마디로 전문 작업을 시킬 수 있습니다.
- 권한을 좁게 주는 것(`toolsSettings`)이 핵심입니다. "테스트 정리 담당"에게는 코드 수정 권한을 주지 않는 식으로, **실수의 범위를 설계 단계에서 차단**합니다.
- Steering(실습 ②)이 "모든 대화에 깔리는 공통 규칙"이라면, Agent는 "특정 작업을 위해 불러내는 전문 역할"입니다. 둘은 함께 쓸 때 가장 강력합니다.
