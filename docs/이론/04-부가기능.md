# 04. Kiro의 부가 기능

> **이 챕터의 목표**
>
> - Steering, Agent, Skills, Hooks, MCP가 각각 무엇인지 이해한다.
> - 각 기능을 "언제" 써야 하는지 구분할 수 있다.
> - 간단한 설정 파일을 직접 만들어 본다.

---

## 한눈에 보기

| 기능               | 한 줄 설명                                   | 역할 비유                    |
| ------------------ | -------------------------------------------- | ---------------------------- |
| **Steering** | 프로젝트 전체에 적용되는 규칙·맥락          | 팀의 "업무 지침서"           |
| **Agent**    | 특정 작업에 맞춘 Kiro 설정(도구·권한·맥락) | 전문 "역할"을 가진 담당자    |
| **Skills**   | 요청에 맞게 자동 활성화되는 전문 능력 묶음   | 필요할 때 꺼내 쓰는 "매뉴얼" |
| **Hooks**    | 이벤트 발생 시 자동 실행되는 작업            | 자동으로 도는 "체크포인트"   |
| **MCP**      | 외부 도구·데이터 소스 연동 표준             | 외부 세계로 통하는 "플러그"  |

이 기능들은 대부분 프로젝트의 `.kiro/` 폴더 아래에 파일로 저장되어 **버전 관리·공유**가 가능합니다.

---

## 1. Steering (스티어링)

### 무엇인가

AI의 행동을 안내(steer)하는 **규칙 파일**입니다. 모든(또는 특정) 상호작용에 추가 맥락과 지침을 넣어줍니다. [02장](./02-ai-dlc.md)에서 본 AI-DLC의 "스티어링 파일"을 제품화한 것입니다.

### 어디에

`.kiro/steering/*.md` (Markdown 파일)

### 무엇을 적나

"기본 상식"이 아니라 **프로젝트 특수 결정**을 적는 것이 핵심입니다.

- 좋은 예: "인증은 JWT 사용", "DB는 DynamoDB 사용", "에러 메시지는 한국어로 반환"
- 나쁜 예(너무 추상적): "좋은 코드를 써라", "보안에 신경 써라"
- 나쁜 예(너무 장황): camelCase/PascalCase 같은 TypeScript 기본 규칙 50개 나열 → 맥락만 잡아먹고 응답이 느려짐

> 💡 Steering은 **"AI를 위한 인수인계 문서"** 입니다. 새 팀원에게 "우리 프로젝트는 이렇게 합니다"라고 알려주는 것과 같습니다. **판단이 갈릴 만한 지점만** 적으세요.

### 적용 방식(포함 모드)

- **항상 포함(기본)**: 모든 상호작용에 적용
- **파일 매칭**: 특정 파일을 열 때만 (front-matter `inclusion: fileMatch` + `fileMatchPattern`)
- **수동**: 채팅에서 `#`로 직접 참조할 때 (`inclusion: manual`)
- **자동**: 요청이 설명과 맞을 때 (`inclusion: auto` + `name` + `description`)

### 예시

```markdown
---
inclusion: always
---
# 코딩 규칙
- 인증: JWT, 액세스 토큰 만료 1시간
- DB: PostgreSQL, 쿼리는 파라미터 바인딩만 사용(SQL 인젝션 방지)
- API 에러 응답: `{ "error": { "code", "message" } }` 형식, 메시지는 한국어
- 모든 신규 기능에 테스트 포함
```

## 2. Agent (커스텀 에이전트)

### 무엇인가

특정 작업에 맞게 Kiro의 동작을 **맞춤 설정**한 것입니다. 어떤 **도구**를 쓸 수 있는지, 어떤 **권한**을 갖는지, 어떤 **맥락**을 자동 포함할지를 정의합니다.

쉽게 말해 **"역할과 도구, 시작 맥락이 정해진 이름 붙은 설정"** 입니다. 매 세션 같은 프롬프트 세팅을 반복하는 대신, 한 번 정의해 두고 팀과 즉시 공유할 수 있습니다.

### 왜 쓰나

- **범위 제한(안전)**: 예를 들어 "git 기록을 읽고 changelog만 쓰는" 에이전트는 셸 접근 없이, 지정된 파일 밖은 건드리지 못하게 묶을 수 있습니다.
- **반복 제거**: 자주 하는 작업의 세팅을 재사용.
- **일관성**: 팀 전체가 같은 역할 설정을 공유.

### 예시 활용

- "리뷰 전담 에이전트": 코드 변경을 리뷰만 하고 수정은 하지 않음
- "문서화 에이전트": 코드 변경에 맞춰 문서만 갱신
- "테스트 작성 에이전트": 테스트 코드 생성에 특화

## 3. Skills (스킬)

### 무엇인가

특정 작업을 위한 **전문 능력과 지식의 묶음**입니다. 요청이 스킬의 설명과 맞으면 Kiro가 **자동으로 활성화**합니다. 채팅에서 `/`를 입력해 슬래시 명령으로 **직접 호출**할 수도 있어, 언제 활성화할지 명시적으로 제어할 수 있습니다.

### Agent와 Skills의 차이

- **Agent**: "누가(어떤 역할·권한으로) 일하는가"를 정의 — 세션 단위 설정
- **Skills**: "어떤 전문 지식/절차를 꺼내 쓰는가" — 필요할 때 로드되는 능력 묶음

> 비유: Agent가 "담당자"라면, Skills는 그 담당자가 필요할 때 펼쳐 보는 "전문 매뉴얼"입니다.

### 활용 예

- 다이어그램 생성 스킬, 특정 프레임워크 마이그레이션 스킬, 사내 배포 절차 스킬 등
- 자주 반복되는 전문 작업을 스킬로 패키징하면, 매번 설명하지 않아도 됩니다.

## 4. Hooks (훅)

### 무엇인가

IDE에서 **이벤트가 발생하면 자동으로 에이전트 작업을 실행**하는 장치입니다. 저장·생성·삭제 같은 순간에 백그라운드로 작업을 돌립니다. [02장](./02-ai-dlc.md)의 "자동 체크포인트"를 제품화한 것입니다.

### 어디에

`.kiro/hooks/<id>.json`

### 트리거 예

- `PostFileSave`: 파일 저장 시 (예: 린트 실행)
- `PostFileCreate` / `PostFileDelete`: 파일 생성/삭제 시
- `UserPromptSubmit`: 사용자가 메시지를 보낼 때
- `Stop`: 에이전트 실행이 끝날 때
- `PreToolUse` / `PostToolUse`: 도구 실행 전/후 (접근 제어 등에 활용)

### 동작 타입

- **command**: 셸 명령 실행 (예: `npm run lint`)
- **agent**: 정해진 프롬프트를 맥락에 추가

### 예시: 저장 시 자동 린트

```json
{
  "version": "v1",
  "hooks": [{
    "name": "Lint on Save",
    "trigger": "PostFileSave",
    "matcher": "\\.(ts|tsx)$",
    "action": { "type": "command", "command": "npm run lint" }
  }]
}
```

> 💡 "AI가 쓴 코드를 또 다른 자동 검사(린터)가 확인"하는 구조 자체가 AI-DLC 철학입니다. AI 출력을 무조건 믿지 않고 **자동으로 검증**하는 장치를 끼워 넣는 것이죠.

## 5. MCP (Model Context Protocol)

### 무엇인가

**외부 도구·데이터 소스를 AI에 연결하는 개방형 표준**입니다. MCP 서버를 등록하면 Kiro가 그 서버가 제공하는 도구를 사용할 수 있습니다. (예: 문서 검색, 외부 API, DB 조회 등)

### 어디에 설정하나

- 워크스페이스: `.kiro/settings/mcp.json`
- 사용자(전역): `~/.kiro/settings/mcp.json`
- 두 설정은 병합되며, 워크스페이스 설정이 사용자 설정보다 우선합니다.

### 예시 설정

```json
{
  "mcpServers": {
    "aws-docs": {
      "command": "uvx",
      "args": ["awslabs.aws-documentation-mcp-server@latest"],
      "env": { "FASTMCP_LOG_LEVEL": "ERROR" },
      "disabled": false
    }
  }
}
```

> 위 예시는 `uvx`(uv 패키지 매니저)로 서버를 실행합니다. 설정을 바꾸면 서버가 자동 재연결되거나 MCP 서버 뷰에서 재연결할 수 있습니다.

## 실습 아이디어

1. **Steering 만들기**: `.kiro/steering/rules.md`에 우리 프로젝트의 "판단이 갈리는 규칙" 3개를 적어보기.
2. **Hook 만들기**: 저장 시 포매터가 돌도록 `PostFileSave` 훅 작성.
3. **MCP 붙여보기**: 문서 검색용 MCP 서버 하나를 등록하고 샘플 질의로 동작 확인.

## 정리

- **Steering**은 규칙, **Agent**는 역할·권한, **Skills**는 전문 능력, **Hooks**는 자동화, **MCP**는 외부 연동이다.
- 대부분 `.kiro/` 아래 파일로 저장되어 **공유·버전관리**가 가능하다.
- 이 기능들은 모두 [02장](./02-ai-dlc.md)의 AI-DLC 철학("좋은 프로세스를 AI에 강제한다")을 실현하는 도구다.
