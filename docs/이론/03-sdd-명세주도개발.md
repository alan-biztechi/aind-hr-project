# 03. SDD: 명세 주도 개발 (Spec-Driven Development)

> **이 챕터의 목표**
>
> - SDD의 개념과 핵심 원칙을 이해한다.
> - Kiro의 Spec 워크플로우(요구사항 → 설계 → 작업 → 구현)를 직접 돌릴 수 있다.
> - 각 단계에서 산출되는 문서(requirements / design / tasks)의 역할을 안다.

---

## 1. SDD란?

**SDD**(Spec-Driven Development, 명세 주도 개발)는 코드를 쓰기 전에 **명세(spec)를 먼저 작성하고, 그 명세를 기준으로 구현**하는 개발 방식입니다.

핵심 원칙은 하나입니다.

> **"생각과 목적의 명확함이 구현에 앞서야 한다."**

요구사항을 이해하고 해결책을 설계하고 구현을 계획하는 데 시간을 투자하면, 불확실성과 재작업이 줄고 **"올바른 것을 올바르게 만들" 가능성**이 올라갑니다.

[02장](./02-ai-dlc.md)에서 본 AI-DLC의 "요구사항 → 설계 → 구현" 단계를, Kiro가 **Spec**이라는 기능으로 구조화한 것이 바로 SDD의 실천입니다.

---

## 2. SDD가 바이브 코딩과 다른 점

|             | 바이브 코딩      | SDD                                    |
| ----------- | ---------------- | -------------------------------------- |
| 시작점      | "앱 만들어줘"    | "이런 요구사항을 만족하는 걸 만들어줘" |
| 모호함 처리 | 구현 후에 드러남 | **구현 전에** 명세 단계에서 잡힘 |
| 산출물      | 코드만           | 요구사항·설계·작업 문서 + 코드       |
| 재작업      | 잦음             | 적음                                   |
| 추적성      | 없음             | 요구사항 ↔ 설계 ↔ 코드 추적 가능     |

Kiro는 요구사항과 제약을 **명시적으로** 만든 뒤 그 명세를 맥락으로 삼기 때문에, 더 적은 반복으로 더 정확하게 작업을 완료합니다.

---

## 3. Kiro Spec 워크플로우

Kiro에서 Spec 세션을 시작하면 다음 3단계 문서가 순서대로 만들어지고, **각 단계마다 사람이 검토·승인**합니다. 보통 `.kiro/specs/<기능이름>/` 아래에 생성됩니다.

```
요청: "사용자 인증 기능을 만들고 싶어"
        │
        ▼
① requirements.md  ─ 무엇을 만들까 (요구사항)
        │  ← 사람 검토·승인
        ▼
② design.md        ─ 어떻게 만들까 (기술 설계)
        │  ← 사람 검토·승인
        ▼
③ tasks.md         ─ 무엇부터 할까 (구현 작업 목록)
        │  ← 사람 검토·승인
        ▼
구현 (작업을 하나씩 실행, 추적 가능)
```

### ① 요구사항 (requirements)

- "무엇을 만들 것인가"를 명확히 합니다.
- 종종 **사용자 스토리 + 수용 기준(acceptance criteria)** 형태로 작성됩니다.
- 예: *"사용자로서 이메일과 비밀번호로 로그인할 수 있어야 한다. 비밀번호는 8자 이상이어야 한다."*

> ✅ 이 단계에서 모호한 요구사항을 질문으로 좁히는 것이 가장 중요합니다. 여기서 잡은 모호함 하나가 뒤의 재작업 열 개를 막습니다.

### ② 설계 (design)

- "어떻게 만들 것인가"를 정합니다. 아키텍처, 데이터 모델, API 설계 등.
- AI가 제안한 설계를 **그대로 승인하지 말고 반드시 검토**합니다.
- 예: 토큰 만료 시간, 저장소 선택(DB 종류), 에러 처리 방식 등 프로젝트 특수 결정을 여기서 바로잡습니다.

### ③ 작업 (tasks)

- 설계를 **원자적인 구현 작업**으로 쪼갭니다.
- 각 작업은 체크 가능한 항목이며, 어떤 요구사항을 만족하는지 추적할 수 있습니다.
- Kiro는 이 목록을 하나씩 실행하며, 완료된 작업을 표시합니다.

## 5. SDD를 잘 쓰는 팁

- **요구사항 단계에 시간을 아끼지 마세요.** 가장 저렴하게 오류를 잡는 단계입니다.
- **설계를 그대로 승인하지 마세요.** AI 제안은 "초안"입니다. 프로젝트 특수 요건을 반드시 반영하세요.
- **작업은 작게.** 한 작업이 너무 크면 리뷰가 어렵고 재작업이 커집니다.
- **Steering과 함께 쓰세요.** 프로젝트 규칙([04장](./04-부가기능.md))을 미리 정의하면 설계·구현이 매번 일관됩니다.

---

## 정리

- SDD는 **명세를 먼저 쓰고 그 명세로 구현**하는 방식이며, 핵심 원칙은 "명확함이 구현에 앞선다"이다.
- Kiro Spec은 **요구사항 → 설계 → 작업 → 구현**의 4단계로 돌아가며, 각 단계마다 사람이 검토·승인한다.
