h2. 0. 이 실습에서 하는 것

* 실습용 저장소를 열고 Kiro에서 작업할 준비를 한다.
* MySQL을 준비하고 {{schema.sql}} / {{data.sql}}로 초기 데이터를 적재한다.
* Spring Boot 백엔드를 실행하고 직원·부서 API가 응답하는지 확인한다.
* (선택) React 프론트엔드를 실행해 전체 화면을 확인한다.

{tip}
이 환경은 *이후 모든 실습(①\~⑥)의 공통 전제*입니다. 여기서 백엔드가 정상 기동되는 것까지 반드시 확인하고 넘어가세요.
{tip}


----

h2. 1. 사전 요구사항

아래가 설치돼 있어야 합니다. 터미널에서 버전을 먼저 확인하세요.

||도구||버전||확인 명령||
|JDK|17|{{java -version}}|
|MySQL|8.x|{{mysql --version}}|
|Kiro|IDE 또는 CLI|IDE 실행 / {{kiro-cli --version}}|
|(FE 실습 시) Node.js|{{\^20.19.0}} 또는 {{>=22.12.0}}|{{node -v}}|

* ☐ JDK 17 설치됨 ({{java -version}}이 17.x)
* ☐ MySQL 8.x 기동 가능
* ☐ Kiro 실행 가능
* ☐ (프론트 실습 시) Node 20.19+ 또는 22.12+

{warning}
Maven은 따로 설치하지 않아도 됩니다. 저장소에 포함된 *Maven Wrapper*({{./mvnw}})를 사용합니다.
{warning}

h2. 2. 저장소 준비

이미 이 저장소를 로컬에 받아 Kiro로 열었다면 이 단계는 건너뛰어도 됩니다.

{code:language=bash}
# 저장소를 clone 한 뒤 (URL은 본인에게 공유된 저장소 주소 사용)
git clone <저장소-URL> aind-hr-project
cd aind-hr-project
{code}

그다음 Kiro로 이 폴더를 엽니다.

* *IDE*: File → Open Folder → {{aind-hr-project}} 선택
* *CLI*: 프로젝트 루트에서 {{kiro-cli}} 실행

{tip}
워크스페이스를 처음 열면 Kiro가 신뢰(trust) 여부를 물을 수 있습니다. 실습을 진행하려면 신뢰를 허용하세요.
{tip}


----

h2. 3. 데이터베이스 준비

h3. 3-1. MySQL 접속

{code:language=bash}
mysql -u root -p
{code}

h3. 3-2. 스키마 + 초기 데이터 적재

MySQL 프롬프트에서 아래를 *순서대로* 실행합니다. (경로는 프로젝트 루트 기준)

{code:language=sql}
source src/main/resources/schema.sql
source src/main/resources/data.sql
{code}

{{schema.sql}}이 {{aind_sample_db}} 데이터베이스와 4개 테이블({{department}}, {{employee}}, {{attendance}}, {{leave_request}})을 만들고, {{data.sql}}이 초기 데이터를 넣습니다.

*적재 후 확인:*

{code:language=sql}
USE aind_sample_db;
SELECT COUNT(*) FROM employee;     -- 15 (직원 15명)
SELECT COUNT(*) FROM department;   -- 5  (부서 5개)
{code}

{warning}
*접속 정보 주의*: {{src/main/resources/application.yml}}에는 접속 정보가 {{username: root / password: root}}로 *평문 하드코딩*되어 있습니다(실습용). 본인 MySQL의 계정/비밀번호가 다르면 이 파일을 본인 환경에 맞게 수정하세요. 이 하드코딩 자체는 *실습 ③(아키텍처 검토)에서 보안 리스크로 다시 다룹니다.*
{warning}

h2. 4. 백엔드 실행 및 확인

프로젝트 루트에서 실행합니다.

{code:language=bash}
# macOS / Linux
./mvnw spring-boot:run

# Windows (cmd / PowerShell)
.\mvnw.cmd spring-boot:run
{code}

{{Started HrApplication ...}} 로그가 뜨면 {{http://localhost:8080}}에서 기동된 것입니다.

*API 응답 확인* (새 터미널에서):

{code:language=bash}
# 직원 목록 (부서명 포함) — 15명이 나와야 함
curl -s http://localhost:8080/v1/employees | head

# 직원 수만 세기 (jq 설치 시) — 15가 나와야 함
curl -s http://localhost:8080/v1/employees | jq 'length'

# 부서 목록 — 5개
curl -s http://localhost:8080/v1/departments

# OpenAPI 문서 (JSON)
curl -s http://localhost:8080/v3/api-docs | head
{code}

*기대 출력* (초기 데이터 기준 — 이런 모양이면 성공):

{code:language=javascript}
// GET /v1/employees 의 첫 번째 직원 (필드/값은 data.sql 기준)
{
  "id": 1,
  "name": "김민수",
  "email": "minsu.kim@aind.co.kr",
  "phone": "010-1234-5001",
  "departmentId": 1,
  "departmentName": "개발팀",   // ← 부서명이 조인되어 포함됨
  "position": "부장",
  "hireDate": "2018-03-15",
  "status": "ACTIVE",
  "createdAt": "...",
  "updatedAt": "..."
}
{code}

{code:language=javascript}
// GET /v1/departments — 부서 5개
[
  { "id": 1, "name": "개발팀",   "description": "소프트웨어 개발 및 유지보수" },
  { "id": 2, "name": "인사팀",   "description": "채용, 교육, 인사관리" }
  // ... 기획팀 / 디자인팀 / 영업팀
]
{code}

{tip}
{{jq}}가 없으면 {{brew install jq}}(macOS)로 설치하면 JSON을 보기 좋게 확인할 수 있습니다. 없어도 {{curl}}만으로 응답은 확인됩니다.
{tip}


브라우저로 *Swagger UI*도 확인합니다: [http://localhost:8080/swagger-ui.html]

* ☐ {{http://localhost:8080}} 기동 로그 확인
* ☐ {{GET /v1/employees}}가 직원 15명을 반환
* ☐ {{GET /v1/departments}}가 부서 5개를 반환
* ☐ Swagger UI에서 employee / department / attendance / leave 태그 확인

{tip}
*주요 API 한눈에 보기* (전체는 루트 {{README.md}} 참고)
{tip}

||도메인||대표 엔드포인트||

h2. 5. (선택) 프론트엔드 실행

React 관리자 화면까지 보고 싶다면, *백엔드를 띄운 상태에서* 별도 터미널로:

{code:language=bash}
cd frontend
npm install
npm run dev
{code}

개발 서버: [http://localhost:5173] Vite dev 서버가 {{/v1/\*}} 요청을 {{http://localhost:8080}}으로 프록시하므로 별도 CORS 설정이 필요 없습니다.

* ☐ (선택) {{http://localhost:5173}}에서 직원/부서 목록이 보인다

{warning}
Node 버전이 낮으면({{node -v}}로 확인) Vite 8 / React Router 7이 실행되지 않습니다. 20.19+ 또는 22.12+ 인지 확인하세요.
{warning}

h2. 6. 완료 체크리스트

* ☐ 저장소를 Kiro로 열었다

* ☐ 백엔드가 실행되고 {{GET /v1/employees}}가 응답한다
* ☐ Swagger UI에 접속된다
* ☐ (선택) 프론트엔드가 실행된다

h2. 7. 흔한 에러 & 해결

||증상||원인||해결||
|{{Access denied for user 'root'}}|{{application.yml}}의 계정/비밀번호가 실제 MySQL과 불일치|{{application.yml}}의 {{username}}/{{password}}를 본인 환경에 맞게 수정|
|{{Unknown database 'aind_sample_db'}}|{{schema.sql}}을 적재하지 않음|{{source src/main/resources/schema.sql}} 먼저 실행|
|백엔드는 떴는데 데이터가 빈 배열 {{\[\]}}|{{data.sql}} 미적재|{{source src/main/resources/data.sql}} 실행|
|{{Port 8080 already in use}}|다른 프로세스가 8080 점유|해당 프로세스 종료 또는 {{application.yml}}의 {{server.port}} 변경|
|{{node: command not found}} / Vite 실행 실패|Node 미설치 또는 버전 미달|Node 20.19+ / 22.12+ 설치|
