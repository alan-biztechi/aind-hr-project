# API 회귀 검증

## 언제 쓰나
- `src/main/` 아래 백엔드 코드를 수정한 직후
- 버그를 고친 뒤 "고친 것"과 "고치다 건드렸을 수 있는 주변"을 함께 확인할 때

## 전제
- 로컬 백엔드가 떠 있고, 수정 사항 반영을 위해 **재시작**했다 (`./mvnw spring-boot:run`)
- 로컬 DB에만 실행한다. 공유·운영 DB에는 실행하지 않는다.
- 데이터를 만드는 호출(POST 등)은 실행 전에 사용자에게 확인한다.

## 절차

### 1. 컴파일
```bash
./mvnw -q compile
```

### 2. 변경 범위
```bash
git status --short -- src
git diff --stat -- src
```
- 백엔드 소스(`src/`)만 본다. `.kiro/` 같은 설정 파일 변경은 대상이 아니다.
- 수정한 파일이 의도한 범위(고친 도메인의 Controller·Service·Repository·Mapper XML) 안에 있는지 본다.
- 범위 밖 파일이 바뀌었으면 보고에 적는다.

### 3. 고친 기능
- 사용자가 알려 준 "고친 동작"을 재현하는 API를 호출하고, 기대한 값이 나오는지 확인한다.
- 사용자가 알려 주지 않았으면 무엇을 고쳤는지 먼저 묻는다.

### 4. 인접 기능 (스모크)
고친 도메인 밖의 기본 조회가 그대로인지 확인한다. 건수는 초기 데이터(`data.sql`) 기준이다.

```bash
curl -s http://localhost:8080/v1/employees   | jq 'length'   # 15
curl -s http://localhost:8080/v1/departments | jq 'length'   # 5
curl -s http://localhost:8080/v1/leaves      | jq 'length'   # 10
```

## 실패 시
- 컴파일 실패: 오류 메시지의 파일:라인을 보고하고 멈춘다.
- 고친 기능이 기대와 다름: 백엔드를 재시작했는지 먼저 확인한다.
- 스모크 건수가 다름: 실습 중 데이터를 추가했을 수 있으니, 사용자에게 데이터를 바꿨는지 확인한다. 바꾸지 않았다면 `git diff`로 범위 밖 변경을 찾는다.

## 보고 형식
| 단계 | 결과 | 근거 |
|------|------|------|
| 1. 컴파일 | 통과 / 실패 | |
| 2. 변경 범위 | 범위 안 / 범위 밖 파일 있음 | 파일 목록 |
| 3. 고친 기능 | 통과 / 실패 | 실제 값 |
| 4. 인접 기능 | 통과 / 실패 | 실제 값 |

실행하지 못한 단계는 실행하지 못했다고 적는다.
