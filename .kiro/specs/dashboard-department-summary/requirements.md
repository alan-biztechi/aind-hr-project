# Requirements Document

## Introduction

기존 HR 관리자 웹(`hr-web-frontend` Spec)의 대시보드 상단에 **부서별 직원 수 요약 카드**를 추가합니다.
HR 담당자가 접속 직후 어느 부서에 인원이 몇 명인지 한눈에 볼 수 있게 하는 것이 목적입니다.

- 데이터 소스는 기존 `GET /v1/employees` 응답(`EmployeeResponse.departmentName`)뿐입니다.
- 집계는 **프론트엔드에서** 수행합니다. 백엔드 코드·API는 수정하지 않습니다.
- 기존 대시보드의 `useEmployees()` 훅(TanStack Query, key `["employees"]`)을 재사용하므로 추가 네트워크 요청을 만들지 않습니다.
- 화면 구성·스타일은 기존 대시보드 카드(`DashboardPage`)와 공통 컴포넌트 컨벤션을 따릅니다.

### 범위 밖 (하지 않는 것)

- 백엔드 코드, 신규 API, DB 변경
- 신규 라이브러리 추가
- 차트/그래프 시각화
- 카드 클릭 시 부서별로 필터링된 직원 페이지로의 이동 (현재 직원 페이지는 라우트로 필터를 받지 않음)

## Requirements

### Requirement 1 — 부서별 인원 요약 카드 표시

**User Story:** HR 담당자로서, 대시보드에서 부서별 직원 수를 카드로 한눈에 보고 싶다.

#### Acceptance Criteria

1. WHEN 대시보드에 진입하면 THEN 시스템은 `GET /v1/employees` 응답을 `departmentName` 기준으로 집계하여, 기존 지표 카드 위(상단)에 부서별 직원 수를 카드로 표시해야 한다.
2. WHEN 부서별 카드를 표시할 때 THEN 시스템은 각 카드에 부서명과 해당 부서의 직원 수를 함께 보여줘야 한다.
3. WHEN 여러 부서가 있으면 THEN 시스템은 직원 수가 많은 순으로 정렬하고, 직원 수가 같으면 부서명 오름차순으로 정렬해야 한다.
4. WHEN 직원 데이터가 변경되어 직원 목록 쿼리가 갱신되면 THEN 시스템은 별도 조작 없이 요약 카드의 수치를 갱신된 데이터로 다시 계산해 표시해야 한다.

### Requirement 2 — 로딩·오류·빈 상태

**User Story:** HR 담당자로서, 데이터를 불러오는 중이거나 실패했을 때도 화면이 어떤 상태인지 알고 싶다.

#### Acceptance Criteria

1. WHEN 직원 데이터를 불러오는 동안 THEN 시스템은 요약 영역에 로딩 상태를 표시해야 한다.
2. IF 직원 데이터 조회가 실패하면 THEN 시스템은 요약 영역에 오류 메시지와 재시도 수단을 표시해야 하며, 기존 지표 카드(부서·직원·출근·휴가)의 표시는 영향을 받지 않아야 한다.
3. IF 조회된 직원이 한 명도 없으면 THEN 시스템은 요약 영역에 "표시할 부서별 인원이 없습니다"와 같은 빈 상태 안내를 표시해야 한다.

### Requirement 3 — 기존 기능 비회귀 및 품질

**User Story:** 개발자로서, 새 기능이 기존 대시보드와 백엔드를 깨뜨리지 않고 타입 안정성을 유지하길 원한다.

#### Acceptance Criteria

1. WHEN 요약 카드가 추가되어도 THEN 시스템은 기존 대시보드 지표 카드 4종(부서 수, 직원 수, 오늘 출근 기록 수, 대기 휴가 수)의 표시와 클릭 이동 동작을 그대로 유지해야 한다.
2. WHEN 집계 로직을 구현할 때 THEN 시스템은 `types/api.ts`의 `EmployeeResponse` 타입을 사용해 타입 안전하게 구현해야 한다.
3. WHEN 구현이 완료되면 THEN `npm run typecheck`와 `npm run build`가 오류 없이 통과해야 한다.
4. WHEN 구현이 완료되면 THEN 백엔드(`src/`, `pom.xml`) 파일은 변경되지 않아야 한다.

## 미결 사항 / 가정

승인 전에 확인이 필요한 항목입니다. 별도 지시가 없으면 아래 **기본 가정**으로 설계를 진행합니다.

| # | 질문 | 기본 가정 | 영향 |
|---|------|-----------|------|
| 1 | 퇴사(`RESIGNED`) 직원도 인원 수에 포함할까? | **포함** (기존 대시보드 "직원" 카드가 `employees.data.length`로 전체를 세므로 일관성 유지) | 수치가 "재직자 수"가 아니라 "등록된 직원 수"가 됨 |
| 2 | 직원이 0명인 부서도 카드로 보여줄까? | **보이지 않음** (요구사항이 `GET /v1/employees` 집계만 사용하도록 한정. 0명 부서까지 보이려면 부서 목록 API를 함께 사용해야 함) | 신규 부서나 빈 부서는 요약에 나타나지 않음 |
| 3 | 부서가 매우 많을 때 전부 표시할까? | **전부 표시** (현재 규모 가정, 반응형 그리드로 줄바꿈) | 부서가 많으면 대시보드가 길어질 수 있음 |
| 4 | 같은 이름의 부서가 둘 이상 있으면? | **`departmentName`이 같으면 하나로 합산** (집계 키가 이름이므로). `departmentId` 기준 집계는 응답에 `departmentId`가 있어 가능하지만, 요청사항이 이름 기준이라 이를 따름 | 동명 부서가 존재하면 합쳐져 보임 |
